# 複習排程邏輯圖

「開始複習」背後的完整決策流程。程式碼都在 `review.js`：`isDue`、`buildQueue`、`schedule`、
`recallOf`、`dueAt`、`debtOf`。

## 一個字的生命週期

```
              點字幕上的字（好奇）───► 只開卡查詢，不進詞彙庫
                        │
                 按「學習中」
                        ▼
              ┌───────────────────────┐
              │ 新字 (fresh)           │  reviews = 0，還沒有 due
              │ 標記當天＝第一次學習    │  當天不進佇列：讀完解釋就是學習事件
              └──────────┬────────────┘
                         │ 隔天凌晨 4 點起到期（睡一覺才做第一次提取）
                         ▼
     ┌────────────────────────────────────────────────────┐
     │ 排程中 (scheduled)   reviews > 0，有 due / interval   │
     │                                                    │
     │   記住了 ──► interval: 1 天 → 6 天 → ×ease（愈拉愈長） │
     │   忘記了 ──► interval 歸 1，ease −0.2，lapses +1      │
     │             （同場 4 張卡後補考一次，不動長期排程）      │
     └─────────┬──────────────────────────┬────────────────┘
               │ 按「已掌握」               │ 標記超過 30 天、一次也沒複習
               ▼                          ▼
     ┌───────────────────┐       ┌──────────────────┐
     │ 已掌握 (suspended)  │       │ 單字負債（清理候選）│──► 清理＝刪除
     │ 留在詞彙庫，永不排程 │       └──────────────────┘
     └───────────────────┘
```

## 今天到期嗎？（isDue）

```
isDue(word, now)
   │
   ├─ suspended（已掌握）？ ────────► 否。永不到期。
   │
   ├─ 有 due？（複習過至少一次）────► due <= now 才到期。
   │                                 「學過的字不再進來」靠的就是這裡：
   │                                 每次評分都把 due 推到未來。
   │
   ├─ 有 addedAt？（新字）─────────► 標記「隔天」凌晨 4 點起到期。
   │                                 剛標的字當天不會出現。
   │
   └─ 都沒有（最早期資料）─────────► 視為到期。
```

到期時間一律貼齊凌晨 4 點的日界（`dueAt`，Anki 的 rollover）：對人來說「明天再複習」
是以天為單位的，睡眠才是間隔的意義。

## 佇列怎麼組（buildQueue）

```
詞彙庫 words
   │
   ├─ filter isDue ──► 到期的字
   │
   ├─ 複習組（有 due）：按 recallOf 由低到高排序
   │       recallOf = 0.9 ^ (距上次複習天數 / interval)
   │       剛好到期 ≈ 0.9；愈接近遺忘排愈前面。
   │       沒有數量上限 —— 逾期的卡不會自己消失。
   │
   └─ 新字組（無 due）：洗牌後最多取 20 個（NEW_PER_SESSION）
           一次標 50 個字，也不會把當天佇列塞爆。
   │
   ▼
每隔 ⌈複習數 ÷ 新字數⌉ 張複習卡，穿插一個新字 ──► 本場佇列
```

## 評分之後（grade → schedule，SM-2）

```
顯示解釋 ──► 記住了 (q=4) ─► reps+1
   │                         interval = 第1次:1天 / 第2次:6天 / 之後: round(interval×ease)
   │
   └──────► 忘記了 (q=0) ─► reps=0，interval=1，lapses+1
                             ease = max(1.3, ease − 0.2)
                             （兩鍵介面下，lapse 是唯一的難度訊號：
                               常忘的字間隔長得比較慢）
   │
   ▼
due = dueAt(now, interval)   ← 隔 interval 天的凌晨 4 點
```

跳過（→）只把卡移到佇列尾，不影響排程；拒答不等於答錯。

## 「待複習 102」是怎麼組成的

儀表板的數字＝**所有** isDue 的字，包含：

```
102 ＝ 逾期／今天到期的複習卡（無上限，會一直累積到你消化掉）
     ＋ 昨天以前標記、還沒複習過的新字（進場每次限 20，但全部都計入數字）
```

所以數字大不代表排程壞了，代表兩件事之一：標記的速度超過複習的速度（每小時 ≤10 的
建議就是為此存在），或有一段時間沒複習、逾期卡堆了起來。

字離開這個數字只有三條路：

1. **評分** —— 記住了或忘記了都會把 due 推到至少明天 4 點以後。
2. **已掌握** —— suspended，永不再排程（統計仍保留）。
3. **刪除** —— 詞彙庫逐字刪，或單字負債批次清理（標記 >30 天、從未複習的死帳）。

消化 backlog 的實際做法：每天固定複習（逾期卡答對後一樣走 1→6→×ease，很快就散開）、
把其實已經會的字按「已掌握」、拿不會再學的字餵單字負債清理。
